# 7. PC インターフェイスケーブルと自作ケーブル

純正の PC インターフェイスケーブル（763-0500900）の構造と、汎用の USB シリアル変換モジュールでケーブルを自作するときの考え方です。

> [!CAUTION]
> この章の配線に関する内容は、写真と取扱説明書から推測したものです。**実機のピン配置と信号レベルは確かめていません。** i-Map 本体のカプラには、センサーやインジェクタの信号、12V の電源線、場合によってはマイコンのリセット端子などが来ている可能性があります。誤った配線は本体を壊すおそれがあるので、必ずテスターで測ってから、自己責任で作業してください。

## 7.1 i-Map 本体側の接続

i-Map 本体の取扱説明書（グロム用 6〜8 ページ、ズーマー用 2 ページ）によると、本体からは次のものが出ています【裏付け】。

| 接続 | 形状 | 用途 |
|---|---|---|
| メインカプラ | 白い 6P カプラ（ズーマー用説明書では「110 型 6P カプラ」） | カプラーオンハーネスを通して、クランク角センサー、スロットル開度センサー、インジェクタにつながる |
| ギボシ端子 | 3 本（赤、黒、黒） | 電源と GND |
| **PC 接続用カプラ** | 本体から出た短い線の先にある防水カプラ。グロム用の製品写真ではゴムのキャップがかぶっている | **PC インターフェイスケーブル専用** |

> [!WARNING]
> 6P のメインカプラは PC 通信用ではありません。シリアル変換モジュールをここにつながないでください。

## 7.2 純正ケーブルの構造

Fuel Manager の取扱説明書（13・22 ページ）と、公開されていた純正ケーブルの中古品の出品写真（6 枚）から読み取れたことです。

| 部分 | 内容 | 確度 |
|---|---|---|
| PC 側 | USB-A のオス | 【観測：写真】 |
| 途中の黒い箱 | USB シリアル変換。Windows には「Silicon Labs CP210x USB to UART Bridge」として認識される | 【裏付け：取扱説明書 13 ページ】 |
| 箱から先のケーブル | 被覆の印字（読み取れた範囲）は `TACHII … E324091 (UL) CL3 90C 4pr24 or AWM 2464 VW-1`。**`4pr24` は 24AWG の 4 ペア、つまり 8 芯** | 【観測：写真】 |
| i-Map 側のカプラ | **2 列 × 4 の 8 極**の防水カプラ。白いハウジングで、差し込み口の内側にオレンジのシール、配線側に青いシールがある。ケーブル側はオス端子で、正面から見ると **8 つの穴すべてに端子が入っている** | 【観測：写真】 |
| 線の色 | 中古品の写真では赤、黄、緑、黒が見え、少なくとも赤は 2 本ある。2014 年版の取扱説明書の写真では黄、白、緑、橙、赤などが見え、製造時期によって色が違う | 【観測：写真】 |

カプラのメーカーとシリーズは、写真からは特定できませんでした。実物のハウジングの刻印を見ると特定できることが多いです。

## 7.3 なぜ 8 極なのか（推測）

シリアル通信に必要なのは TX、RX、GND の 3 本です。それなのに 8 芯のケーブルを使い、8 極すべてに端子を入れています。考えられる理由は次のとおりです（すべて【推測】）。

1. **部品の都合**：4 ペア 8 芯のケーブルは安く手に入ります。GND や電源を 2 本ずつにしているだけかもしれません。
2. **CP210x の信号をまとめて引き出している**：電源（USB の 5V）、GND、TXD、RXD、RTS、CTS、DTR、DSR で、ちょうど 8 本前後になります。
3. **ケーブルの接続を検出している**：ケーブルの中で 2 本のピンをつないでおき、i-Map が PC ケーブルの接続を判断する仕組み。取扱説明書の「エンジン始動後は通信しない」という記述とも合います。
4. **ファームウェアの書き込みを兼ねている**：リセット端子やブートモード端子をカプラに出し、CP210x の DTR や RTS で切り替えてマイコン内蔵のブートローダに入る設計（[9 章](09-firmware.md)）。

Fuel Manager は DTR も RTS も操作しません（[4.1 節](04-serial-protocol.md#41-物理層と回線設定)）。そのため、2 や 4 が正しくても、**通常のマップの読み書きに必要なのは TX、RX、GND（と、もしかすると電源）だけ**のはずです。

## 7.4 汎用モジュールでの自作

### 使えるモジュールの条件

- USB シリアル変換チップを積んだものなら、基本的には使えます。純正と同じ CP210x 系（CP2102 など）なら、ドライバも同じです。
- Fuel Manager は「開けた COM ポート」を使うだけで、USB の VID/PID を確かめません（[4.2 節](04-serial-protocol.md#42-com-ポートの選び方)）。そのため、**自作ケーブルでも純正の Fuel Manager がそのまま使える**はずです【推測】。
- i-Map 側の信号レベル（5V TTL、3.3V TTL、RS-232）がわからないので、**複数の信号レベルに切り替えられるモジュール**が便利です。たとえば作者が用意したのは、CP2102 を積み、TTL（5V / 3.3V）、RS-232、RS-485 をスイッチで切り替えられ、DTR と RTS のピンもある汎用モジュール（DAOKAI WE-DA-178）です。

### 測定の手順

i-Map 本体側の 8 極カプラ（メス側）を、テスターで 1 ピンずつ測ります。**電圧を測るだけ**にして、ピン同士やピンと GND を短絡させて反応を見ることはしないでください。

1. ピンの位置（上段左から 1〜4、下段左から 5〜8 など）と線の色を記録します。
2. **キー OFF**：各ピンとバッテリーのマイナスの導通を見ます。導通するピンが GND です。ピン同士の導通も見て、本体の中でつながっているピンを記録します。
3. **キー ON、エンジンは止めたまま**：残りのピンと GND の間の電圧を測ります。

| 測った電圧 | 考えられること |
|---|---|
| 約 5V / 3.3V | i-Map の出力（TX など）、またはプルアップされた入力（RX、リセット端子など） |
| 0V で、GND とは導通しない | PC 側からの信号や電源を待っている入力の可能性 |
| −5〜−12V | RS-232 レベルの信号 |
| 約 12V | 電源線。**絶対にモジュールにつながない** |

### 配線の方針

1. モジュールの信号レベルを、測った電圧に合わせます（TTL 5V / 3.3V / RS-232）。
2. 最初は **GND、TX、RX の 3 本だけ**つなぎます。モジュールの RX を i-Map の TX に、モジュールの TX を i-Map の RX につなぎます。
3. TX と RX がどちらかわからないうちは、モジュールの TX に **1kΩ くらいの抵抗を直列に**入れておきます。出力同士がぶつかっても壊れにくくなります。
4. **役割のわからないピンは何もつながず開けておきます。** モジュールの DTR、RTS、電源出力（5V / 3.3V）もつなぎません。電源が必要だとわかった場合だけ追加します。
5. 最初は**読み出し（`m`）だけ**試します。マップ番号とデータが返ってくれば、配線は正しいです。書き込みは、読み出しが安定して成功するようになってからにします（[6.6 節](06-implementation-guide.md#66-実機で初めて試すときの手順)）。

付属のジャンパ線などを端子に差して仮に試すこともできます。ただ、接触不良は書き込み中の通信断につながります。本番では同じシリーズの相手側カプラを用意したほうが安全です。

### 確実な方法

純正ケーブルが手に入るなら、**箱を開けて、8 極のピンがそれぞれ CP210x のどの足につながっているかをテスターで追う**のが一番確実です。i-Map 本体ではなくケーブルなので、開けても問題ありません。これで 7.3 節の候補を絞り込めて、自作ケーブルの配線もそのまま写せます。
