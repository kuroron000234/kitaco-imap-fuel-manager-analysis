# 9. ファームウェアについての考察

i-Map 本体のファームウェアは**解析していません**。この章では、解析できるかどうかと、ファームウェアの書き込み経路について、わかっている範囲の考察をまとめます。

## 9.1 ファームウェアの入手可能性

| 入手の方法 | 状況 |
|---|---|
| 公式の配布 | なし。i-Map の配布ページにあるのは PC ソフトとマップデータだけ |
| PC ソフトの更新機能 | なし。Fuel Manager が使うコマンドは `m` と `s` だけ（[4.3 節](04-serial-protocol.md#43-コマンドと記号の一覧)） |
| 公開されている更新情報 | 検索した範囲では、KITACO が i-Map のファームウェア更新を提供していたという情報は見つからなかった |
| 本体から読み出す | 本体を分解し、マイコンの書き込み端子から読み出すしかない。市販品の多くは読み出し保護（コードプロテクト）が有効なので、読み出せる見込みは低い |

作者は、本体を分解したり改造したりする方法はとらないことにしました。読み出し保護を回避する行為は本体を壊すリスクが高く、法的にもグレーになり得ます。

ファームウェアの中身（ダンプ）が手に入れば、Ghidra などで解析できます。調べられるのは次のような点です。

- 補正の計算方法
- 回転数制限の実装
- `m` と `s` 以外のコマンドがあるか
- 範囲外の値を受け取ったときの扱い

## 9.2 ファームウェアの書き込み経路（推測）

i-Map が外部とつながる手段は、メインカプラ（センサー、インジェクタ用）、電源、PC 接続用の 8 極カプラの 3 つだけです。工場でのファームウェアやプリセットマップの書き込み経路としては、次の候補が考えられます。プリセットマップは車種やバージョンで中身が違うので、何らかの方法で書き込まれているはずです。

| 候補 | 内容 | 純正ケーブルで書けるか |
|---|---|---|
| A. 基板上の書き込み端子 | 工場でケースに入れる前に、基板の端子から書き込む。**一般的にはこれが一番多い** | 書けない（8 極カプラは通信専用） |
| B1. 書き込み専用の端子を 8 極カプラに出している | ICSP や SWD などの端子を外に出し、専用の書き込み器（PICkit など）で書き込む | 書けない（別の書き込み器が必要） |
| **B2. マイコン内蔵のシリアルブートローダ** | TX、RX に加えて、**リセット端子とブートモード端子**をカプラに出す。CP210x の **DTR と RTS** でリセットとモードを切り替える（Arduino や ESP32 の自動書き込みと同じ仕組み）。Renesas、STM32、NXP LPC、MSP430 などが標準で対応している | **書ける（純正ケーブルが書き込みケーブルを兼ねる）** |
| B3. ファームウェア自体に更新機能を入れる | 独自のブートローダと専用の PC ソフトで更新する | 公開されている PC ソフトにはその機能がない |

### 今ある根拠

| 根拠 | B2 との関係 |
|---|---|
| 純正ケーブルは CP210x（DTR と RTS がある）を使い、8 芯ケーブルで 8 極すべてに端子が入っている（[7.2 節](07-pc-interface-cable.md#72-純正ケーブルの構造)） | B2 と合う。ただし「部品の都合」でも説明できる |
| Fuel Manager は DTR も RTS も操作しない | 「通常の通信ではブートモードに入らない状態を保っている」とも読めるので、B2 と矛盾しない |
| Fuel Manager にも同じ会社のデータロガー用ソフトにも、i-Map のファームウェアに関わる処理はない（[8 章](08-development-traces.md)） | B3 の可能性は低い |

どの候補が正しいかは**判断できません**【不明】。

## 9.3 自作ケーブルへの影響

B2 が正しい場合、8 極カプラの残りのピンには**マイコンのリセット端子やブートモード端子**が来ている可能性があります。そこに、

- 汎用モジュールの DTR や RTS をつなぐ
- ピンを GND や電源に短絡させる

といったことをすると、通信中に i-Map が**リセットされたり書き込みモードに入ったりする**おそれがあります。ブートローダに誤ったデータが届けば、ファームウェアやマップの領域が壊れる可能性もあります。

そのため、自作ケーブルでは次のことを守ってください（[7.4 節](07-pc-interface-cable.md#74-汎用モジュールでの自作)）。

- 最初は GND、TX、RX の 3 本だけつなぐ。
- 役割のわからないピンは**何もつながず開けておく**。普通は、i-Map の基板側で通常動作の状態になるよう固定されているはずです。
- 電圧を測るのはよいが、**ピンを短絡させて反応を見ることは絶対にしない**。

## 9.4 本体を開けずに確かめる方法

- **純正ケーブルの箱を開ける**：CP210x の DTR と RTS の足が 8 極カプラのピンまで配線されていれば、B2 の可能性がかなり高くなります。配線されていなければ、A か「部品の都合」です。
- **外から動作を観測する**：ロジックアナライザやオシロスコープでインジェクタの駆動信号を測り、マップを変えたときの噴射時間の変化を見ます。補正の計算方法や頭打ちの制御など、ファームウェアの動作の一部は外から確かめられます。
- **未知のコマンドを送って探ることは勧めません。** 消去や上書きのコマンドに当たると、マップやファームウェアの領域が壊れるおそれがあります。
